# PPT Logic Builder

> 一句话：用户想做PPT但还没想清楚讲什么时，先访谈+定逻辑骨架，产出文字大纲让用户确认，再选对外/对内档位，最后调用pptx skill出片——绝不跳过大纲直接生成文件。

大多数"用AI做PPT"失败，不是输给设计，而是输给逻辑。AI一上来就编内容、排版式，等用户发现"这页不该放这"时，已经返工整份PPT。

核心主张：**把"想清楚讲什么"和"做成什么样"拆成两个阶段，中间设文字检查点**。改一行大纲比改一页设计便宜得多。

```
访谈（定骨架）→ 纯文字大纲 → 用户确认 → 选档位 → 调用pptx skill生成文件
```

阶段1只产文字大纲，不碰排版配色。阶段2才出片。**绝不要跳过阶段1直接生成文件**。

---

## 阶段1：访谈，产出大纲

### Step 0 — 先看用户手上有多少东西

扫一眼初始消息，按情况分流。**不确定时问用户，不要替用户决定**：

- **已有完整大纲**（结构化逐页内容）：跳过Step 1-3，问"是要我直接生成，还是先帮你检查一下逻辑？"
- **有素材但不成体系**（笔记、数据、零散想法）：正常走完整访谈，直接复用素材
- **只有主题词**（"做个产品介绍PPT"）：正常从Step 1开始

猜错会损害已有结构，不确定就问。

### Step 1 — 问目的，定骨架

问："这次PPT是要说服/争取（对外提案、客户演示），还是同步信息/汇报（内部汇报、总结）？"

说服和汇报需要不同叙事结构，不要混用。完整骨架见 `references/logic-frameworks.md`：

- **说服类**：问题→代价→方案→证据→行动呼吁。倒逼出让听众"必须行动"的理由。
- **汇报类**：现状→数据→分析→建议→下一步。清楚可回溯，方便事后翻看。

场景模糊时读框架中"混合场景处理"小节，不要替用户归类。

### Step 2 — 补齐剩余信息

目的确定后，补齐以下信息。一次问1个：

1. **听众**：对方是谁？已经知道什么？最关心什么？疑虑是什么？
2. **一句话核心**：对方只记住一句话，希望是哪句？—— **PPT锚点，没有它不要排页**。用户答不上来，退回去先理清目的或听众。
3. **支撑点**：论据/数据/案例。允许用户乱序输出，你负责归类。**遇到不确定的专业术语**直接向用户确认，不要脑补。
4. **篇幅与场合**：几页、几分钟、什么场合（口头讲/自行阅读/正式评审）？影响每页信息密度。

第1-2项必答；3-4项可来回补充。

### Step 3 — 按固定模板输出大纲

严格按这个结构输出，不要自由发挥：

```markdown
【核心信息】一句话，这份PPT最想让人记住什么

【整体逻辑】所用骨架 + 具体顺序

第1页｜标题：____
    核心信息：（只一句——每页只能有一个核心）
    支撑内容：（要点…）
    建议呈现方式：（数据→图表；流程→流程图；观点→文字。起点不是死规定）

第2页｜标题：____
   （同结构）

【自检】
- 前后页是否衔接？有没有跳跃？
- 有没有一页塞了两个核心？拆页。
- 听众最大的疑虑有没有被回应到？
```

**强制约束**：每页只一个核心信息。发现两件事就拆成两页，不要妥协。

### Step 4 — 等用户确认，不自动进阶段2

请用户检查大纲："重点看顺序对不对、有没有该删改的——这一步改字比之后改片子省事。"

用户明确认可后（包括"可以，开始做"），才能进入阶段2。

**用户在确认时提出结构调整**（合并/拆页/调顺序）：直接按修改刷新完整大纲并再次请用户确认。不要只口头改一行描述就跳进阶段2——结构调整会波及多页的核心信息和逻辑衔接，必须落回完整的文字版本让人审。刷新后仍从"请检查"开始。

**用户拒绝继续回答访谈时**：不要卡住。基于已有信息产出一版最简大纲（保留核心信息+页面列表），让用户确认方向。比无限追问或直接跳到生成都好。

## 阶段2：选档位，生成PPT文件

### Step 1 — 确认档位

问："这次是对外场合（提案/客户演示）还是对内场合（内部汇报）？"（阶段1已问过则直接复用）

决定设计精度：
- **对外**：配色统一、留白讲究、图表精致，每页信息量少、靠口头讲解补充
- **对内**：简洁清楚优先，信息密度更高，方便自行翻看回顾

不影响阶段1已定的大纲和逻辑顺序。

**对外细分**：若用户只笼统说了"对外"没说明对象，补问一句（客户？投资人？渠道？），让设计判断更准。问完靠判断力调整，不要变成新分类体系。

### Step 2 — 调用 pptx skill 生成文件

先确认 `pptx` skill 是否在当前 session 中可用。如果不可用，告知用户当前缺 pptx skill，无法自动生成 .pptx 文件，并提供下一步建议（安装该 skill 或手动转制）。

skill 可用时，**用大纲确认过的标题、核心信息、顺序作为输入**，不在生成时改动内容结构——发现大纲有问题就回阶段1修正，不在生成阶段直接改逻辑。

**关于模板**：生成前检查 `assets/templates/` 目录（当前为空）。对应档位的模板文件存在时，让 pptx skill 走"基于模板编辑"路径（套入内容，不自由设计）。文件不存在时按默认流程生成。命名规则见 `references/template-usage.md`。

### Step 3 — 修改回路

生成后用户要改，先判断属于哪一层：

- **逻辑层**（这页该不该在这、核心信息对不对）→ 回阶段1改大纲，确认后再重新生成
- **设计层**（配色、排版、字体，但逻辑没问题）→ 阶段2层面直接调，不回大纲

告诉用户"这是逻辑问题还是设计问题"让修改更精准。

**每次逻辑层修改确认后，重新输出完整大纲**（哪怕只改了一页），保证任意时刻有唯一可信的当前状态。

## 常见偏差

- **直接跳过大纲**：哪怕用户说"随便弄"，也先给最简大纲（核心信息+页面列表）一闪而过确认
- **每页堆多个核心**：发现即拆页，不因"页数变多"妥协
- **素材乱**：你负责归类去重，不要求用户先整理
- **骨架混用**：拿不准时重新确认目的，不凭经验猜
